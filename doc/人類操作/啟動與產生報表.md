# 啟動與產生報表

已有 JAR 的主機只需要 Java 17。從原始碼建置請看 [Gradle離線建置](../人類部署與建置/Gradle離線建置.md)。

## 1. 確認資料與設定位置

以下以正式主機為例：

```text
/app/fsap-monitor-util/
  fsap-monitor-util-0.1.0-SNAPSHOT.jar
  config/application.yml
  fsap-month-report-develop/
    00_info/           交易名稱與主機對照資料
    01_excel_input/    每日 Excel 原檔
    02_source_lake/    轉換後的 JSONL.GZ
    03_sql_logic/      views 與 reports SQL
    04_report_output/  產出的 Excel、CSV
    05_database/       DuckDB 資料庫
    logs/              執行紀錄
```

連線設定放在 JAR 旁的 `config/application.yml`，Web 與 CLI 都會讀取。修改後需重啟服務或重新執行指令。程式也會讀取工作目錄的外部設定，建議固定在 JAR 目錄執行。

在目標主機以服務帳號執行以下設定；後面的 `fsap` 是此 Shell 工作階段的指令簡寫：

```bash
cd /app/fsap-monitor-util
fsap() {
  /app/java/java17/bin/java \
    -Djava.io.tmpdir=/app/fsap-monitor-util/tmp \
    -jar /app/fsap-monitor-util/fsap-monitor-util-0.1.0-SNAPSHOT.jar \
    --fsap.paths.base-dir=/app/fsap-monitor-util/fsap-month-report-develop "$@"
}
mkdir -p /app/fsap-monitor-util/tmp
fsap doctor
```

請依主機調整 Java 與安裝路徑。暫存目錄條件見 [暫存目錄與上傳設定](暫存目錄與上傳設定.md)。`doctor` 成功後再匯入。

## 2. 匯入每日 Excel

將 `FSAP每日交易統計YYYYMMDD.xlsx` 直接放進 `01_excel_input/`，不要再包一層子目錄。也可以透過 Web 上傳，或使用 [SFTP下載](SFTP下載與上傳.md)。

```bash
fsap ingest
```

此指令掃描全部符合命名規則的 Excel，將尚未存在的分頁資料寫入 `02_source_lake/`。

| 情況 | 指令 | 行為 |
| --- | --- | --- |
| 補回大量歷史檔案 | `fsap ingest` | 不限制數量，已存在的輸出會跳過 |
| 只處理某天 | `fsap ingest --date 20260801` | 按檔名日期篩選 |
| 更正已匯入的某天 | `fsap ingest --date 20260801 --force` | 覆寫該天 Excel 所含目標分頁的輸出 |
| 日常只檢查最新三份 | `fsap ingest --limit 3` | 只檢查最新三份，不會繼續往前補漏 |

若曾在匯入中途失敗，既有輸出不代表內容完整，請對失敗日期使用 `--force` 重建。完成後查看摘要的 `failure=0` 與 `logs/ingest.log`。

## 3. 產生報表

```bash
fsap sync-views
fsap generate-report --target-month 2026-08
```

將範例月份改成要產出的月份。`generate-report` 也會自動同步 views；單獨執行 `sync-views` 可先確認 SQL 與來源資料是否正常。

| 設定 | 預設值／用途 |
| --- | --- |
| `--target-month YYYY-MM` | 未指定時為主機日期的上個月，不是最新 Excel 的月份 |
| `--history-start-month YYYY-MM` | 歷史比較起月，預設 `2025-09` |
| `--history-end-month YYYY-MM` | 歷史比較迄月，預設目標月份 |
| `--range-start-date`、`--range-end-date` | 日期區間，格式 `YYYY-MM-DD`；預設目標月首日至末日 |
| `--range-start-time`、`--range-end-time` | 時間區間，格式 `"YYYY-MM-DD HH:mm"`；預設上述日期的 `00:00` 至 `23:59` |
| `--continue-on-error` | SQL 失敗仍繼續；只要有失敗，指令最後仍回報失敗 |

各參數影響哪些分頁，請看 [報表SQL說明](../人類報表與資料/報表SQL說明.md)。補入多個月份只會補資料，不會自動產生每月一份報表；需要補發的月份請分別執行。

成品在 `04_report_output/<執行時間>/`，包含彙總 Excel、各分頁 CSV 與 `report-params.json`。確認 Console 顯示 `failure=0`，並核對月份與資料筆數。來源缺日不一定會讓產報失敗。

## 4. 用網頁操作

沿用上方 Shell 設定：

```bash
fsap serve --port 18080
```

開啟 `http://主機位址:18080/`。在 `Operations` 依序執行 **Doctor → Ingest → Sync Views → Generate Report**，完成後從報表批次清單下載 Excel。

- 後端會限制上述任務順序；重做前一步會重設後續狀態。
- 上傳 Excel 只是存檔，還需要執行 Ingest。
- Web 預設可操作；只開查詢與下載可用 `fsap serve --port 18080 --readonly`。
- 任務狀態保存在記憶體，重啟後清空；已保存的資料與報表仍在磁碟。
- 需要監控 CSV 與圖表時，執行 `fsap update-monitor-data`，再查看 `Monitor Dashboard`。

本機開發與 Eclipse 斷點設定見 [專案維護指引](專案維護指引.md)。

## 5. Jenkins 補檔與排程

| Job | Pipeline 檔案 | 現行流程 |
| --- | --- | --- |
| 每日產報 | `Jenkinsfile` | doctor → download-input → ingest --limit 3 → sync-views → generate-report |
| 月報上傳 | `Jenkinsfile.upload` | doctor → generate-report → upload-report |

大量補檔時，先手動執行完整 `ingest`，或暫時將每日 Job 的 `fsapCommand('ingest --limit 3')` 改為 `fsapCommand('ingest')`。

已有當日 Excel 時，每日 Job 可能在 `download-input` 因同名檔停止；補檔可直接從手動匯入開始。兩個 Job 的執行期間應錯開，避免同時存取相同 DuckDB 與報表目錄。

排程由 Jenkins Job 設定。要每月 2 日上傳，就將月報 Job 設在 2 日，並確保每日 Job 已成功完成。月報 Job 不會匯入缺漏資料。

## 出問題時查哪裡

| 現象 | 先檢查 |
| --- | --- |
| 找不到 Excel | 檔名、`base-dir`、檔案是否直接位於 `01_excel_input/` |
| 補了檔仍缺資料 | 是否仍有 `--limit 3`；`logs/ingest.log` 是否跳過或失敗 |
| 報表月份不對 | 傳入 `--target-month`，核對 `report-params.json` |
| SQL 或報表失敗 | `logs/report_execution.log`、來源資料與 `00_info/` 是否齊全 |
| `/tmp/libduckdb_java...so` 載入失敗 | [暫存目錄與上傳設定](暫存目錄與上傳設定.md) |
| SFTP 失敗 | [SFTP下載與上傳](SFTP下載與上傳.md) |

其他選項可用 `fsap --help` 或 `fsap ingest --help` 查詢。
