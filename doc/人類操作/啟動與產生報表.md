# 啟動與產生報表

已有 JAR 的主機只需要 Java 17，不需要 Python、Gradle 或資料庫伺服器。原始碼建置見 [Gradle離線建置](../人類部署與建置/Gradle離線建置.md)。

## 1. 確認資料與設定

```text
/app/fsap-monitor-util/
  fsap-monitor-util-0.1.0-SNAPSHOT.jar
  config/application.yml
  config/monitor-data.json
  fsap-month-report-develop/
    00_info/           主機與交易詳細參考資料
    01_excel_input/    每日 Excel
    02_source_lake/    匯入後的 JSONL.GZ，包含 PR_CFG
    03_sql_logic/      views 與 reports
    04_report_output/  月報與監控匯出
    05_database/       DuckDB
    logs/             執行紀錄
```

交易名稱與分類來自 `PR_CFG`，不是 `00_info/`。Git 不包含正式資料或分類快照，首次部署請準備來源資料；不能只複製 JAR 就產報。

建議固定在 JAR 目錄執行，並明確指定外部設定。以下 `fsap` 是目前 Shell 的指令簡寫，路徑請依主機調整：

```bash
cd /app/fsap-monitor-util
mkdir -p /app/fsap-monitor-util/tmp
fsap() {
  /app/java/java17/bin/java \
    -Djava.io.tmpdir=/app/fsap-monitor-util/tmp \
    -jar /app/fsap-monitor-util/fsap-monitor-util-0.1.0-SNAPSHOT.jar \
    --spring.config.additional-location=file:/app/fsap-monitor-util/config/application.yml \
    --fsap.paths.base-dir=/app/fsap-monitor-util/fsap-month-report-develop "$@"
}
fsap doctor
```

設定與指令的順序：JVM `-D...` 在 `-jar` 前，Spring `--...=值` 在子指令前，子指令選項在子指令後。`base-dir` 是資料根目錄，不是外部設定檔的位置。

穩定預設留在 JAR；連線、部署與業務規則集中在外部 config/application.yml，分工與升級方式見 [設定檔分工與覆寫](設定檔分工與覆寫.md)。缺少外部報表的分類、總覽分頁或分類分頁清單時，產報會直接中止，不會改用內建分類或默默降成 ALL。

`doctor` 只檢查必要目錄、DB／log 寫入與 DuckDB 連線；不驗證 SFTP、分類快照、SQL 正確性或資料是否完整。暫存權限見 [暫存目錄與上傳設定](暫存目錄與上傳設定.md)。

## 2. 匯入每日 Excel

將 `FSAP每日交易統計YYYYMMDD.xlsx` 直接放進 `01_excel_input/`。也可透過 Web 上傳或 [SFTP下載](SFTP下載與上傳.md)，完成後仍須執行 ingest。

| 情況 | 指令 |
| --- | --- |
| 正常匯入、補大量歷史檔 | `fsap ingest` |
| 指定檔名日期 | `fsap ingest --date 20261001` |
| 更正或重建失敗日期 | `fsap ingest --date 20261001 --force` |
| 日常只檢查最新三份 | `fsap ingest --limit 3` |

`--limit 3` 在檢查既有輸出前先截取最新三份，不會往前補漏。已存在的分頁輸出會跳過；匯入失敗可能留有不完整檔，應對失敗日期用 `--force`。Web 上傳同名 Excel 會取代來源檔，但不會自動重建數據湖。

查看 `failure=0` 與 `logs/ingest.log`。缺少選配分頁不一定失敗，但報表需要的資料缺檔會在同步或產報時失敗。

## 3. 產生月報

```bash
fsap sync-views
fsap generate-report --target-month 2026-10
```

`generate-report` 本身也會同步 views；前面的 sync 可先檢查問題。補入多個月份不會自動各產一份月報，補發月份須逐次指定。

| 選項 | 規則 |
| --- | --- |
| `--target-month YYYY-MM` | 建議明確指定；未給月份與日期／時間時，使用主機日期的上個月，不看 Excel 檔名 |
| `--history-start-month`／`--history-end-month` | 預設 `2025-09` 至目標月；起月是隱藏比較基底 |
| `--range-start-date`／`--range-end-date` | `YYYY-MM-DD`，預設目標月首日至末日 |
| `--range-start-time`／`--range-end-time` | `"YYYY-MM-DD HH:mm"`，預設上述日期的 00:00 至 23:59 |
| `--target-bzkinds NCL,NIS` | 額外分類；省略用設定，`--target-bzkinds=` 只產 ALL |
| `--continue-on-error` | SQL 失敗後繼續，但最終仍回報失敗，不代表成品可用 |
| `--timestamp YYYYMMDDHHmm` | 指定批次目錄；請用新的 12 位時間，重用可能覆寫，其他格式無法被自動上傳選取 |

若不給 target-month 但有日期／時間，程式會依序從迄日、起日、迄時、起時推導月份。各參數影響範圍見 [報表SQL說明](../人類報表與資料/報表SQL說明.md)，不要以為每份報表都使用自訂時間區間。

### 依業務分類產出

ALL 一律先計算；預設再計算 NCL、NCB、BIS、FAC、FAS、NIS、FSAP。FSAP 是單一分類，不是 ALL；FAC 與 FAS 也是不同分類。分類與名稱取最新 PR_CFG，重跑舊月份也使用最新分類。

最新快照若缺少有效交易類別（PR_TPKIND 必須為 1 或 2），產報會中止；指定分類不在快照內則略過，原因見 Console 的 Notice。分類摘要僅用來核對各類程式數與當月有交易程式數。

外部設定中的分類設定如下；這只是分類部分，總覽與分類分頁兩份清單也必須保留：

```yaml
fsap:
  report:
    target-bzkinds: [NCL, NCB, BIS, FAC, FAS, NIS, FSAP]
    combined-workbook:
      bzkinds: [NCL, NCB, BIS, FAC, FAS, NIS, FSAP]
```

兩份清單各有用途：前者決定要計算哪些分類，後者決定正式月報選哪些分類及順序。清單整份取代，不會自動與內建值合併。

分頁清單的完整範本是 [config/application.yml](../../config/application.yml) 中的 `fsap.report`，不再放入 JAR。外部 `all-sheets`／`reports` 應同步新版清單，不能直接刪除期待採用內建值；四種日期／峰值分頁採 2.1、3.1、5.1、6.1 的 Pivot CSV，歷史月總量仍用 4。舊 `combined-workbook.filename` 已不使用。

預設正式月報是 10 個總覽＋7 分類各 8 頁＝66 頁，總覽包含全系統 TOP6交易類與 TOP6查詢類。ALL 的全部 CSV 與完整原始彙總在 `SUM/`，分類輸出在分類子目錄；根目錄是正式月報與 `report-params.json`，沒有 REPORT 目錄。結構見 [報表輸出目錄](../人類報表與資料/報表輸出目錄.md)。

確認 `failure=0`、Notice、月份與資料完整度後才使用或上傳。缺日不一定失敗；月末資料通常還需要次月首日來源檔。

## 4. Web 與監控

```bash
fsap serve --port 18080
```

開啟 `http://主機位址:18080/`。Operations 依序執行 Doctor → Ingest → Sync Views → Generate Report。任務順序只在 Web 流程內生效，重啟會清空狀態；CLI／Jenkins 不共用這個鎖。

Web 預設可操作；`serve --readonly` 會停用任務與上傳。這不是使用者權限或完整 SQL 安全隔離。查詢與 API 見 [網頁查詢與API](網頁查詢與API.md)，監控匯出見 [監控資料匯出](監控資料匯出.md)，Eclipse 與除錯見 [專案維護指引](專案維護指引.md)。

## 5. Jenkins 排程

| Job | Pipeline | 流程 |
| --- | --- | --- |
| 每日產報 | `Jenkinsfile` | doctor → download-input → ingest --limit 3 → sync-views → generate-report |
| 每月產報上傳 | `Jenkinsfile.upload` | doctor → generate-report → upload-report |

兩份 Pipeline 都使用 `/app/fsap-monitor-util/tmp`，只執行已部署的 JAR，不負責更新程式。排程在 Jenkins Job 設定，程式沒有內建每天或每月自動排程。

月報 Job 可排每月 2 日，應晚於每日 Job 完成；它不下載也不匯入缺漏資料。兩個 Job 都設 03:30 並不會互相等待，`disableConcurrentBuilds()` 也只限制各自 Job，必須錯開或由 Jenkins 串接。

大量補檔先手動執行不限數量的 ingest，再產報。每日 Job 若下載到本機已存在的同名檔，會停止，不會自行跳過進入下階段。SFTP 目的地與手動補發見 [SFTP下載與上傳](SFTP下載與上傳.md)。

## 常見問題

| 現象 | 先檢查 |
| --- | --- |
| 找不到或未補齊 Excel | base-dir、檔名、是否直接放輸入目錄、有無 limit |
| 產報失敗 | `logs/report_execution.log`、最新 PR_CFG 類別、SQL 與來源缺檔 |
| FSAP 或 Pivot 分頁未出現 | 分類是否在快照內、外部兩份分類清單及分頁清單是否仍是舊值 |
| 月份／峰值數字不符預期 | `report-params.json` 與 [公式口徑](../人類報表與資料/報表公式與口徑.md) |
| `/tmp` 或上傳暫存失敗 | [暫存設定](暫存目錄與上傳設定.md) |

完整選項以 `fsap --help` 與各子指令 `--help` 為準。
