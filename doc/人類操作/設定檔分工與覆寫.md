# 設定檔分工與覆寫

## 兩份檔案各放什麼

| 位置 | 用途 | 目前內容 |
| --- | --- | --- |
| `src/main/resources/application.yml` | 穩定的程式預設，打包進 JAR | 程式名稱、Jasypt 加密器 bean、input／source-lake／SQL／report 的固定子目錄名稱、view 同步預設輪數 |
| `config/application.yml` | 會隨環境或業務變動的外部設定，不包進 JAR | HTTP port、模板快取、上傳限制、SFTP 連線、資料根目錄／DB／log 路徑、匯入分頁與檔名規則、分類與月報分頁、Web readonly、monitor 配置路徑 |
| `config/monitor-data.json` | 監控匯出的任務清單 | view、daily／hourly、輸出目錄與檔名 |

完整業務設定範本以 [config/application.yml](../../config/application.yml) 為準；[JAR 內預設](../../src/main/resources/application.yml) 不再包含分類或月報分頁清單。

固定目錄名稱仍可由外部 `fsap.paths` 同名設定覆寫，但日常只需調整 base-dir、database-file 與 log-dir。不要為了新增分類或分頁修改 resources 後重新打包。

## 部署與讀取

```text
/app/fsap-monitor-util/
  fsap-monitor-util-0.1.0-SNAPSHOT.jar
  config/
    application.yml
    monitor-data.json
```

CLI 與 Web 都使用這份外部設定。程式透過 Spring Boot ApplicationHome 找到 JAR 所在目錄，再補讀該目錄與其 config 子目錄；工作目錄的 Spring 外部設定位置仍有效。開發 bootRun 在專案根目錄執行，會讀專案的 config/application.yml。

若同時存在多份設定，部署時可明確指定檔案以避免混淆：

```bash
java -jar /app/fsap-monitor-util/fsap-monitor-util-0.1.0-SNAPSHOT.jar \
  --spring.config.additional-location=file:/app/fsap-monitor-util/config/application.yml \
  --fsap.paths.base-dir=/app/fsap-monitor-util/fsap-month-report-develop \
  generate-report --target-month 2026-10
```

明確的命令列同名設定優先於設定檔，外部設定優先於 JAR 內預設。Spring 選項放在子指令前；JVM 的 `-Djava.io.tmpdir=...` 放在 `-jar` 前。

修改外部設定後，Web 需重啟，CLI 下次執行生效；不是存檔後立即熱更新。這類調整不需重新打包 JAR。修改 Java 或 JAR 內預設才需要重新打包。

## 缺少報表設定會中止

產報前必須明確提供三份清單，不能只部署舊版只有 remote／paths 的外部設定：

- `fsap.report.target-bzkinds`
- `fsap.report.combined-workbook.all-sheets`
- `fsap.report.combined-workbook.reports`

任一份缺少時，CLI／Web 產報會回報 `Missing required report settings in external config/application.yml` 並列出缺少的鍵，不建立報表批次、不開啟 DB，也不默默產成 ALL 月報。doctor、help 與 Web 啟動仍可執行，方便排查設定。

若確實只需要 ALL，仍須明確提供設定；空清單代表有意停用，而不是漏部署。例如：

```yaml
fsap:
  report:
    target-bzkinds: []
    combined-workbook:
      all-sheets: []
      reports: []
```

分類清單、分頁清單是整份取代，不會與其他來源的清單逐項合併。combined-workbook.bzkinds 可留空，表示依本次實際產出的分類順序。

## 升級時怎麼做

1. 備份正式環境原有 config/application.yml。
2. 合併新版的匯入與報表設定，保留原有 remote、port、資料與暫存路徑；不要直接用開發環境連線值覆蓋。
3. 將新 JAR 與外部設定一起部署，重新啟動後試產，核對分類、66 頁分頁與 failure=0。

本次是將設定移出 JAR；**只換新 JAR 而不補齊外部報表設定，會刻意中止產報**。後續單純調整分類與分頁，改外部檔即可，操作見 [啟動與產生報表](啟動與產生報表.md)。
