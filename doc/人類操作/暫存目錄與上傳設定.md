# 暫存目錄與上傳設定

這些設定可在啟動時或外部設定檔調整，不需重打包 JAR。修改後要重新啟動服務。

## DuckDB 原生函式庫載入失敗

若出現 `/tmp/libduckdb_java...so: failed to map segment from shared object`，請先確認主機的 `/tmp` 是否掛載為 `noexec`。可將 JVM 暫存位置改到管理員允許載入原生函式庫的目錄。

在目標主機以服務帳號建立專用目錄：

```bash
mkdir -p /app/fsap-monitor-util/tmp
chmod 700 /app/fsap-monitor-util/tmp
```

目錄必須屬於服務帳號且可讀寫、可進入；所在掛載點須允許原生程式碼載入。單純 chmod 無法解除 `noexec`。仍失敗時需由管理員檢查主機安全政策。

啟動參數放在 `-jar` 前面，值不可留空：

```bash
java -Djava.io.tmpdir=/app/fsap-monitor-util/tmp \
  -jar /app/fsap-monitor-util/fsap-monitor-util-0.1.0-SNAPSHOT.jar \
  --fsap.paths.base-dir=/app/fsap-monitor-util/fsap-month-report-develop doctor
```

這只改變 JVM 暫存位置，不會搬移或清除資料庫、來源資料或報表。

## 網頁上傳暫存位置

在 JAR 旁的 `config/application.yml` 合併以下設定，保留同一份檔案內其他設定：

```yaml
spring:
  servlet:
    multipart:
      location: /app/fsap-monitor-util/upload-tmp
      max-file-size: 200MB
      max-request-size: 200MB
```

先建立 `upload-tmp`，確保服務帳號可讀寫、可進入且空間足夠。單檔與整次請求的上限目前都是 200MB；多檔上傳時總和也受請求上限限制。

| 位置 | 保存什麼 |
| --- | --- |
| `java.io.tmpdir` | DuckDB 原生函式庫與其他 JVM 暫存檔 |
| `spring.servlet.multipart.location` | HTTP 上傳請求的磁碟暫存檔 |
| `<base-dir>/01_excel_input/*.uploading` | 程式搬存 Excel 時的中間檔 |
| `<base-dir>/01_excel_input/*.xlsx` | 上傳完成的原始 Excel |

只改 multipart 設定不會改變 `.uploading` 或 Excel 最終位置。上傳暫存檔不需要執行程式碼，所在檔案系統可保留 `noexec`；目錄本身仍需進入權限。

## Jenkins 要改哪裡

程式由 SSH 在目標主機以 `apuser` 執行。目錄也必須建在目標主機；只改 Jenkins agent 的暫存設定不會傳到遠端。

目前倉庫中的兩份 Jenkinsfile 尚未帶入上述 JVM 參數。部署時可在 `Jenkinsfile` 與 `Jenkinsfile.upload` 的欄位區加入：

```groovy
@Field String javaTmpDir = '/app/fsap-monitor-util/tmp'
```

將兩份檔案的 `fsapCommand` 改為：

```groovy
def fsapCommand(String command) {
    return [
        "mkdir -p \"${javaTmpDir}\"",
        "cd \"${installDir}\"",
        "/app/java/java17/bin/java -Djava.io.tmpdir=\"${javaTmpDir}\" -jar \"${installDir}/${jarName}\" --fsap.paths.base-dir=\"${baseDir}\" ${command}"
    ].join('\n')
}
```

multipart 設定只影響 Web 上傳，不影響這兩個批次 Job 的 SFTP 傳輸。
