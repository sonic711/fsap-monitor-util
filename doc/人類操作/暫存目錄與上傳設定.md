# 暫存目錄與上傳設定

下列設定不需重新打包 JAR。Web 修改後須重啟，CLI 下次執行時生效。

## DuckDB 暫存目錄

若出現 `/tmp/libduckdb_java...so: failed to map segment from shared object`，先確認 `/tmp` 是否掛載為 noexec 或受到其他安全政策限制。以服務帳號在允許載入原生函式庫的位置建立專用目錄：

```bash
mkdir -p /app/fsap-monitor-util/tmp
chmod 700 /app/fsap-monitor-util/tmp
```

目錄須屬於執行帳號、可讀寫且可進入，掛載點須允許原生函式庫載入。chmod 不能解除 noexec；仍失敗需由管理員檢查政策。

JVM 參數放在 `-jar` 前，值不可留空：

```bash
java -Djava.io.tmpdir=/app/fsap-monitor-util/tmp \
  -jar /app/fsap-monitor-util/fsap-monitor-util-0.1.0-SNAPSHOT.jar \
  --fsap.paths.base-dir=/app/fsap-monitor-util/fsap-month-report-develop doctor
```

這只改暫存位置，不會搬移或清空 DB、數據湖或報表。

## HTTP 上傳暫存

在原有外部 `config/application.yml` 合併，不要覆蓋連線設定：

```yaml
spring:
  servlet:
    multipart:
      location: /app/fsap-monitor-util/upload-tmp
      max-file-size: 200MB
      max-request-size: 200MB
```

先建立 upload-tmp，確認帳號可讀寫、可進入且空間足夠。上限同時受單檔與整次請求限制。

| 位置 | 內容 |
| --- | --- |
| `java.io.tmpdir` | DuckDB 原生函式庫與其他 JVM 暫存 |
| `spring.servlet.multipart.location` | HTTP multipart 磁碟暫存 |
| `<base-dir>/01_excel_input/*.uploading` | 程式搬存中的 Excel |
| `<base-dir>/01_excel_input/*.xlsx` | 上傳完成的來源 Excel |

multipart 設定不改變最終 Excel 與 `.uploading` 的位置，也不影響 SFTP。上傳同名 Excel 會替換來源檔；更新數據湖還要執行指定日期的 `ingest --force`。

## Jenkins 現況

目前 `Jenkinsfile` 與 `Jenkinsfile.upload` 已共同使用 `javaTmpDir=/app/fsap-monitor-util/tmp`，每次指令先 mkdir，再以 `-Djava.io.tmpdir` 啟動 Java。**不需要再次補同一段程式。**

若 Jenkins 是手動貼 Pipeline，請同步成倉庫版本；若使用 Pipeline from SCM，確認載入正確檔案與分支。目錄在 SSH 目標主機，不是在 Jenkins agent；改 agent 的暫存設定不會自動傳入遠端。

Jenkins 只執行目標主機既有 JAR。push、修改 Pipeline 與部署 JAR 是不同步驟，詳見 [正式環境更新](../人類部署與建置/正式環境更新步驟.md)。
