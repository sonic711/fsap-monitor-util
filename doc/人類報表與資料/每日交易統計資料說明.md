# FSAP 維運月報自動化中心 - 知識庫：FSAP 每日交易統計資料說明

## 1. 檔案概述 (Overview)
本文件詳細說明 FSAP 生產環境每日自動產出的數據統計檔案。這些檔案是「FSAP 維運月報自動化中心」的核心原料。

- **檔案名稱規範**：`FSAP每日交易統計YYYYMMDD.xlsx`
- **資料性質**：兼具「秒級明細」與「小時彙總」，涵蓋即時交易、批次作業與系統監控三大範疇。
- **儲存位置**：專案中的 `01_excel_input/` 目錄。

---

## 2. 核心分頁 (Sheets) 內容摘要
每一份 Excel 檔案包含多個分頁，分別對應不同的維運監控維度：

### 📊 即時交易類 (Real-time)
- **`RT_CNT` (Real-time Count)**：
    - **用途**：當日各流程交易總量統計。
    - **重點欄位**：總筆數、成功/失敗量、逾時量、首末筆交易時間。
- **`RT_PR_HH24` (Real-time Process Hourly)**：
    - **用途**：依「小時」聚合的流量與效能。
    - **指標**：每小時平均回應時間 (AVG_TM)、交易筆數 (CNT)。
- **`RT_500_TMSPT` (Slow Transactions)**：
    - **用途**：自動篩選出處理耗時 > 500ms 的慢交易明細，用於效能診斷。
- **`RT_ERR` (Real-time Error)**：
    - **用途**：即時交易失敗的錯誤明細。

### ⚙️ 批次作業類 (Batch)
- **`BT_CNT` (Batch Count)**：
    - **用途**：當日批次作業的執行概況統計。
- **`BT_NODE` (Batch Node Detail)**：
    - **用途**：批次流程內各個處理節點的開始/結束時間與耗時。

### 🛡 系統監控類 (Monitoring)
- **`ERR_LOG` (Error Log)**：
    - **用途**：系統發生的嚴重錯誤日誌，包含主機名稱與詳細訊息。
- **`MON_LOG` (Monitor Log)**：
    - **用途**：系統監控告警事件紀錄。

---

## 3. 資料處理生命週期 (Lifecycle)
這些原始 Excel 資料進入系統後，會經歷以下階段：

1.  **數據標準化 (Ingest)**：
    - 透過 `step1_ingest.py` 讀取 Excel。
    - 清洗無效字元，補足 Metadata（如 `_file`, `_dt`）。
    - 轉換為壓縮 JSON Lines 格式存入 `02_source_lake`。
2.  **邏輯轉化 (Transform)**：
    - 透過 `step2_report.py` 與 SQL View。
    - 將交易代碼 (PR_ID) 關聯中文名稱。
    - 排除 FAC2FAS 等特定基礎交易（依報表需求）。
3.  **報表產出 (Report)**：
    - 彙整為月度維運報表。

## 4. 詳細資料結構 (Schema Dictionary)

| 分頁 (Table) | 關鍵識別 (Primary Key) | 關鍵指標 (Core Indicators) |
| :--- | :--- | :--- |
| **RT_CNT** | `CALDY + PR_ID` | 總筆數、成功、逾時 (TIMEOUT) |
| **RT_PR_HH24** | `PR_ID + CALTM` | AVG_TM (平均耗時), CNT (筆數) |
| **ERR_LOG** | `CREATETIME + PR_ID + TX_NO` | HOSTNAME, SEVERITY, MSG |
| **BT_NODE** | `PR_ID + SUB_PR + CALTIME` | STATUS, TMSPT (耗時) |
| **RT_500_TMSPT** | `PR_ID + RTPR_OID` | PRTMSPT (流程總耗時), NODE_ID |

> **提示**：完整的欄位定義請參考同目錄的 [資料結構說明](資料結構說明.md)。

---

## 5. 使用規範
- 檔案必須符合 `YYYYMMDD` 命名規則。
- 嚴禁手動修改原始 Excel 內容，以確保數據追溯性 (Data Lineage) 的正確。
- 若分頁結構發生異動，需同步更新 `schema/*.schema.jsonl` 定義檔。
