# 報表 SQL 說明

用下表找 Excel 分頁對應的 SQL。檔案位於 `<base-dir>/03_sql_logic/reports/`，編號也是報表分頁的排序依據。

| SQL 編號 | 報表內容 | 閱讀重點 |
| --- | --- | --- |
| `1` | 當月交易概況 | 月總量、交易量峰日與峰日內峰時 |
| `1.1`、`1.1.1` | CPU／記憶體監控 | 區間平均及每日統計；`1.1.1` 共 9 欄：日期、主地／異地的 CPU 與記憶體每日平均（4 欄）、主地／異地的 CPU 與記憶體每日最大（`_max`，4 欄，為各台當日最大值再取平均） |
| `1.1.2` | CPU／記憶體監控-峰日峰時 | 峰日與峰時（以交易量為準）的主地、異地使用率，平均與最大各一列，共 4 列 |
| `1.1.3` | CPU／記憶體監控-峰日每小時 | 峰日 00 至 23 點每小時的交易量與使用率，固定 24 列 |
| `1.1.4` | CPU／記憶體監控-每日每小時列表 | 區間內每天每小時一列的交易量與使用率（整月約 720 列） |
| `2`、`2.1` | 當月每日交易量 | 同份數據的直向與橫向表 |
| `3`、`3.1` | 峰日的小時分佈 | 先找交易量最大日，再展開該日小時數據 |
| `4`、`4.1` | 歷史月總量 | 依歷史起迄月比較，不固定只有半年 |
| `5`、`5.1` | 歷史峰日 | 比較每月最高日交易量 |
| `6`、`6.1` | 歷史峰日峰時 | 先找各月峰日，再找峰日內峰時 |
| `7`、`7.1`、`7.2` | 交易量排行 | 全類別及 update／query 分類 Top 6 |
| `8` | 各交易類別詳細資訊 | 峰日是每日平均處理時間最高日；峰時是區間內交易量最高小時 |
| `8.1` | 前月與本月詳細比較 | 比較交易量、處理時間、峰日與峰時 |
| `8.2` | 前月與本月簡易比較 | 交易量、佔比、增減筆數與變化率 |
| `8.3` | MOM 交易量比較 | 使用 `v_monthly_transaction_stats` 比較兩月 |

交易量的主要來源是 `RT_PR_HH24` 小時資料，CPU／記憶體使用監控 views。具體公式、排除條件與峰值定義請查 [報表公式與口徑](報表公式與口徑.md)，資料來源查 [ViewSQL說明](ViewSQL說明.md)。

## 調整報表月份與區間

使用 `generate-report` 參數或 Web 表單即可，不必修改 SQL 中的 `${...}`。每次產出會保存 `report-params.json`，用來核對實際參數。

| Placeholder | 輸入來源 | 影響報表 |
| :--- | :--- | :--- |
| `${targetBzkind}` | 每輪代入一個業務分類；`ALL` 表示不篩選 | 除 `1.1` 至 `1.1.4`（CPU／記憶體監控）外的所有報表 |
| `${targetMonth}` | UI/CLI `--target-month`；未指定時為上個月 | `1`、`1.1.2`、`1.1.3`、`2`、`2.1`、`3`、`3.1`、`7`、`7.1`、`7.2`、`8`、`8.3` |
| `${rangeStartDate}` / `${rangeEndDate}` | CLI/API 可覆寫；未指定時為目標月首日與末日 | `1.1`、`1.1.1`、`1.1.4` |
| `${historyStartMonth}` / `${historyEndMonth}` | UI/CLI 設定；未指定時為 `2025-09` 至目標月 | `4`、`4.1`、`5`、`5.1`、`6`、`6.1` |
| `${rangeStartTime}` / `${rangeEndTime}` | CLI/API 可覆寫；未指定時為目標月 `00:00` 至 `23:59` | `8.1`、`8.2` |
| `${previousTargetMonth}` / `${previousRangeStartTime}` / `${previousRangeEndTime}` | 由 `targetMonth` 自動推導前一個月 | `8.1`、`8.2`、`8.3` |

UI 目前只提供 `targetMonth`、`historyStartMonth`、`historyEndMonth`；日期與時間區間由後端推導。`7.1` 與 `7.2` 的交易類別分別固定在 SQL 中為 `update` 與 `query`，尚未開放為 UI/CLI 參數。

## 依業務分類篩選

除 `1.1` 至 `1.1.4`（CPU／記憶體監控）外，所有報表都以 `pr_bzkind = ${targetBzkind}` 篩選；`${targetBzkind}` 為 `ALL` 時不篩選，結果與未加入分類功能前相同。

CPU／記憶體監控（`1.1` 至 `1.1.4`）以主機為單位，不依業務分類篩選。Java 版每一輪（`ALL` 與各分類）都會執行所有報表，所以各分類資料夾與活頁簿裡也會有內容相同的這幾張報表；`1.1.4` 約 720 列，重複的份數較大，內容不影響各分類報表的數字。

- 要產出哪些分類由 `--target-bzkinds` 或設定 `fsap.report.target-bzkinds` 決定，見 [啟動與產生報表](../人類操作/啟動與產生報表.md)。
- 分類來自 `PR_CFG`（見 [ViewSQL說明](ViewSQL說明.md) 的 `v_cfg_pr_bzkind`）；不在 `PR_CFG` 的程式歸「其他/待分類」，只會出現在 `ALL`。報表 7、8 系列的交易類別（`update`／`query`）與名稱也取自 `PR_CFG`（類別由 `PR_TPKIND` 決定），所以這些報表只列出 `PR_CFG` 內有的程式。
- 指定分類時，報表內的總量與佔比都以該分類為範圍：有佔比欄的 `7`、`7.1`、`7.2`、`8.1`、`8.2` 分母為該分類的當月總量；`8`、`8.3` 在分類輪改取 `v_monthly_transaction_stats` 的「分類內佔比」（分母同為該分類當月總量），輸出欄名不變。
- 分類沒有資料時，動態 PIVOT 報表（`2.1`、`3.1` 等）沿用既有處理，輸出「Message」提示頁。

操作範例見 [啟動與產生報表](../人類操作/啟動與產生報表.md)。
