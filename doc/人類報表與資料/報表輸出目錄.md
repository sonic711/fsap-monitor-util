# 報表輸出目錄

Java 的 `generate-report` 將成品寫入 `<base-dir>/04_report_output/<執行時間>/`。預設時間格式為 `yyyyMMddHHmm`，12 位數字，使用執行 JVM 的時區。

| 檔案 | 用途 |
| --- | --- |
| `維運月度報表_08月彙總_<執行時間>.xlsx` | 範例為 8 月正式月報，包含總覽與各分類的比較分頁，供下載與預設 SFTP 上傳 |
| `report-params.json` | 本批次實際使用的月份、日期與業務分類參數 |
| `SUM/*.csv` | ALL（不分類）的全部報表查詢結果，含直向與 Pivot 版本 |
| `SUM/維運月度報表_08月彙總_<執行時間>.xlsx` | ALL 的原始完整彙總，每支 SQL 各一頁，不同於根目錄的跨分類正式月報 |
| `<分類>/` | 各業務分類（如 `NCL/`、`NIS/`、`FSAP/`）的完整 CSV 與原始彙總 Excel，檔名含分類代碼，例如 `維運月度報表_08月彙總_NCL_<執行時間>.xlsx` |

不再建立 `REPORT/` 或命名為 `比較_彙總_*.xlsx`。新的跨分類正式月報改用原本月報檔名，直接放在批次根目錄；SFTP 預設選取這份檔案，不會自動上傳 `SUM/` 或各分類子目錄。

第二頁「總覽-CPU-MEM峰日峰時」取自 `SUM/1.1.2. CPU-MEM監控-峰日峰時.csv`，包含全平台交易量峰日／峰時的主地、異地 CPU／Memory 平均與最大使用率，共 4 列。不按業務分類拆分，也不在各分類重複加入。

「總覽-TOP6交易類」與「總覽-TOP6查詢類」分別取自 `SUM/7.1.交易量統計-TOP6交易類.csv`、`SUM/7.2.交易量統計-TOP6查詢類.csv`，是全系統（ALL）的排行，放在「總覽-MOM交易量比較」之前。各分類原有的 TOP6 分頁仍保留。

`FSAP/` 只包含 `PR_BZKIND=FSAP` 的交易，與 `SUM/` 的 ALL 不同；`FAS/` 與 `FAC/` 也分別產出，不會合併。預設七種分類都成功產出時，正式月報包含 10 個總覽與每分類 8 頁，共 66 頁，其中有 8 個 `FSAP-` 與 8 個 `FAS-` 分頁。總覽與各分類的當月每日、峰日峰時、歷史峰日及歷史峰日峰時，均取既有 Pivot SQL 的橫向結果。

只產 ALL、停用比較或無可組合分頁時，根目錄正式月報改用 `SUM/` 的 ALL 彙總，仍可下載與上傳。舊批次不會自動搬移；部署新版後請用新的執行時間產報，避免和舊目錄內容混用。

資料夾名稱是執行時間，不是報表月份。核對月份請看 `report-params.json`。同一分鐘重跑或重用 `--timestamp` 可能覆寫同批次檔案，不能把時間目錄視為保證不覆寫的版本備份。

即使 SQL 失敗也可能留下 Excel，請確認執行結果的失敗數為零再使用成品。

report-params 記錄的是補齊後的請求參數，不是產報成功清單；分類不存在而略過時仍要核對 Notice。完整成功時目前每輪有 23 支 SQL，預設 ALL＋7 類共 184 次查詢，與正式月報的 66 個分頁是兩種不同數量。

`update-monitor-data` 另將監控 CSV 與 JS 寫到 `04_report_output/monitor-data/`。保留與歸檔期限依實際需求訂定，清理時需區分月報批次與監控輸出。

產報步驟見 [啟動與產生報表](../人類操作/啟動與產生報表.md)，上傳規則見 [SFTP下載與上傳](../人類操作/SFTP下載與上傳.md)。
