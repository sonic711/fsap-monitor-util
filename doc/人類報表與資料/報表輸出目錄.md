# 成品庫目錄說明 (04_report_output)

本目錄作為「報表產出引擎」的最終目的地，存放由 `step2_report.py` 自動產出的所有維運月報成果。系統採用「時間戳歸檔」機制，確保每一批次的報表皆有完整的歷史追溯性。

---

## 1. 目錄結構與歸檔機制

系統會在每次執行報表產出時，於本目錄下建立一個以執行時間為名稱的子目錄，格式為 `YYYYMMDDHHMM`。

```text
04_report_output/
├── 202604201030/       # 範例：2026/04/20 10:30 產出的報表
│   ├── 匯總報表.xlsx   # 彙總後的總表
│   ├── 1.交易量統計.csv
│   └── ...
└── 202604210900/       # 下一次產出的歸檔目錄
```

---

## 2. 檔案格式說明

產出的報表包含兩大類核心文件，滿足不同維運需求：

### 📊 彙總 Excel 報表 (`.xlsx`)
- **定位**：供維運主管或報表閱覽人員直接開啟檢視。
- **特色**：包含系統總覽、每日統計、趨勢比較等分頁，所有數據皆經過格式化。

### 📉 SQL 獨立 CSV 檔 (`.csv`)
- **定位**：供進階分析人員 (Data Analyst) 進行二次加工或匯入監控平台。
- **特色**：
    - 結構化數據：欄位名稱精確對應 SQL 視圖。
    - 格式優化：支援 UTF-8-BOM 編碼，確保 Excel 開啟時中文不會亂碼。

---

## 3. 維護建議

### 檔案清理 (Retention Policy)
成品庫隨時間累積會佔用大量空間，建議遵循以下維護守則：
- **保留策略**：建議保留最近 6 個月的報表資料以供歷史對比。
- **定期存檔**：超過 6 個月的產出目錄可打包並移至離線儲存空間 (Cold Storage)。
- **自動清理 (選填)**：若需自動化清理，可編寫簡單的 Bash 腳本刪除舊於特定天數的子目錄：
  ```bash
  # 刪除 180 天前的產出目錄
  find 04_report_output/ -maxdepth 1 -type d -mtime +180 -exec rm -rf {} \;
  ```

### 權限管理
由於報表可能包含敏感的交易統計資料，建議：
- 將 `04_report_output/` 目錄的讀取權限限制在維運管理人員範圍內。
