# 資料庫目錄說明 (05_database)

本目錄為專案的「儲存核心」，存放本專案所有 SQL 邏輯、分析資料的實體執行環境。

---

## 1. 核心檔案說明
- **`fsap-month-report.duckdb`**：這是系統的**核心資料庫檔案**。
    - **本質**：DuckDB 是一個嵌入式 (Embedded) 資料庫，所有的數據模型、視圖邏輯與聚合後的統計資料皆被序列化儲存於此單一檔案中。
    - **特性**：它不需要啟動傳統的資料庫伺服器 (如 Oracle/PostgreSQL)，由程式直接讀取該檔案進行高速的向量化查詢。

## 2. 目錄職責
- **數據持久化**：作為 `step1_ingest.py` (ETL) 與 `step2_report.py` (報表產出) 之間的核心中轉站。
- **視圖中繼站**：存放經 `update_views_to_db.py` 處理後，已將 SQL 視圖固化 (Materialized) 的結構，供 API Server 與查詢儀表板進行高效率存取。

## 3. 維護與備份建議

### 備份策略 (Backup)
由於資料庫為單一檔案，備份極其簡單：
- **冷備份**：在程式未執行時 (無連線寫入)，直接複製 `fsap-month-report.duckdb` 檔案即可完成完整備份。
- **雲端備份**：建議將備份檔定期上傳至專案的歸檔區，以確保若檔案損毀時能快速還原。

### 維護與檢查
- **空間管理**：若發現檔案體積異常膨脹，可執行 DuckDB 的 `VACUUM` 指令進行空間重整：
  ```sql
  -- 使用 duckdb CLI
  VACUUM;
  ```
- **完整性檢查**：若懷疑資料庫損毀，可透過 DuckDB CLI 連線並執行 `PRAGMA integrity_check;`。

### 安全與存取
- **權限控制**：因為資料庫檔案包含了所有的業務與監控數據，請限制此目錄的讀寫權限，僅允許執行維運腳本的服務帳號存取。
